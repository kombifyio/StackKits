Connect this device to your homelab

On your next device open {{.SetupURL}}.

Keep this phone or laptop on the same home network as the server. This setup page opens by IP without DNS or certificate setup. Your apps use HTTPS and need the two steps below on each new device.

Before installing trust: compare this SHA-256 certificate fingerprint with the one printed in the server's install terminal (or its .stackkit/access.json). Stop if they differ. This page uses HTTP and cannot authenticate the server for you.

{{.Fingerprint}}

Your homelab DNS server is {{.Address}}; the private name suffix is {{.Domain}}. Use the instructions for this device:

iPhone or iPad (Safari)
  1. Open Settings → Wi-Fi → ⓘ beside this network → Configure DNS → Manual. Save the existing entries so you can restore Automatic later. Remove those entries, add {{.Address}}, then Save. This changes DNS only for this Wi-Fi network.
  2. Download the public homelab CA certificate in Safari. In Settings → General → VPN & Device Management (or Profile Downloaded), open the downloaded certificate profile, compare its fingerprint above and tap Install. Then Settings → General → About → Certificate Trust Settings → enable full trust for this homelab root. If profile installation is managed by an employer, use an unmanaged device.

Return to Safari and open the Hub below. To undo: remove this profile and restore Configure DNS → Automatic.

Android (Chrome)
  1. Settings → Network & internet → Internet → this Wi-Fi network → Edit → Advanced → IP settings → Static. Keep the current IP address, gateway and prefix length; set DNS 1 to {{.Address}} and remove unrelated DNS 2 entries. Save. If a custom Private DNS provider or browser Secure DNS overrides Wi-Fi DNS, turn it off for home use. Menu names vary by manufacturer.
  2. Download the public homelab CA certificate. Open Settings → Security & privacy → More security settings → Encryption & credentials → Install a certificate → CA certificate; select the download and approve only after comparing its SHA-256 fingerprint with the terminal. Android may display a network-monitoring notice because you approved a CA.

Chrome uses user-installed CAs; some native apps do not. Use the browser Hub first. To undo: remove this CA under Trusted credentials → User and restore Wi-Fi IP settings → DHCP and your previous Private DNS setting.

Windows (Edge or Chrome)

Download root.cer. Open it → Details → Thumbprint algorithm SHA-256 (or run certutil -hashfile "$HOME\Downloads\root.cer" SHA256 in PowerShell). Compare with the terminal. Then open PowerShell as Administrator:

Add-DnsClientNrptRule -Namespace ".{{.Domain}}" -NameServers "{{.Address}}" -Comment "StackKits {{.Domain}}"
Import-Certificate -FilePath "$HOME\Downloads\root.cer" -CertStoreLocation Cert:\LocalMachine\Root

This DNS rule applies only to your homelab suffix. Restart the browser. To undo, remove the rule with this comment in Get-DnsClientNrptRule using Remove-DnsClientNrptRule, and remove the matching certificate in certlm.msc → Trusted Root Certification Authorities.

macOS (Safari or Chrome)

Download root.cer. In Terminal, run shasum -a 256 ~/Downloads/root.cer and compare with the terminal fingerprint above. Then add DNS for this suffix only:

sudo mkdir -p /etc/resolver
printf 'nameserver {{.Address}}\n' | sudo tee /etc/resolver/{{.Domain}}
sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain ~/Downloads/root.cer

Approve the OS prompts, then restart the browser. To undo: remove /etc/resolver/{{.Domain}} and this certificate from the System keychain in Keychain Access.

Linux desktop (NetworkManager)

The existing StackKits trust adapter installs DNS for this suffix and this public CA. It requires NetworkManager, dnsmasq, OpenSSL, update-ca-certificates, NSS certutil and runuser. On Ubuntu/Debian, install missing dependencies with sudo apt install network-manager dnsmasq-base openssl ca-certificates libnss3-tools util-linux.

Download enroll-linux.sh. Before executing it, run sha256sum ~/Downloads/enroll-linux.sh. Compare the entire file's SHA-256 with the Linux adapter SHA-256 printed in the install terminal (also clientTrust.linuxProfileSha256 in the server's access.json). A CA fingerprint alone does not authenticate a shell script. Stop on a mismatch; never use a digest supplied only by this HTTP page as your trust source. The expected file digest shown here for comparison is {{.LinuxSHA256}}. After the independent terminal comparison, approve it from your desktop user's Terminal:

cd ~/Downloads
sudo sh enroll-linux.sh --approve

Restart your browser. To undo only this profile: sudo sh enroll-linux.sh --remove. If Firefox uses its own trust store, import root.cer under Settings → Privacy & Security → Certificates → View Certificates → Authorities and allow website identification.

Open your first app

After DNS and CA trust, open the Hub. For a new homelab, create your Pocket ID owner passkey, then sign in and open your apps from the Hub. DNS and CA approval grant no service session or device credential.

If names do not resolve, check that this device is on the same network (not guest Wi-Fi with client isolation), and that a VPN, Private DNS or browser Secure DNS is not overriding your home DNS. If HTTPS warns, recheck the installed CA fingerprint; do not bypass the warning. These settings work at home; remote access is a separate, explicit choice.
