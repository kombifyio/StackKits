# Moving a server to another network

A StackKits server stays on DHCP and binds its site listeners and the LAN
resolver record to the address it had at install. When you carry it to another
network (new subnet, new gateway, possibly WiFi only) that address is stale.
`stackkit network` makes the move recoverable without a visit by the owner.

## Before the move

Stage the destination WiFi while the server still has its wired connection:

```sh
printf '%s' "$WIFI_PASSPHRASE" | sudo stackkit network wifi add --ssid OfficeNet --password-stdin
stackkit network wifi list
```

- NetworkManager is used when it is running (a keyfile under
  `/etc/NetworkManager/system-connections`, autoconnect on any wireless
  device, `--priority` honoured). Otherwise netplan: StackKits owns
  `/etc/netplan/90-kombify-wifi.yaml` (mode 0600, a `wl*` match with DHCP).
  It never writes an ethernet definition and does not change the global
  renderer, so wired DHCP stays as it is.
- netplan changes are only generated by default; the live connection is not
  disturbed. They apply at the next boot, or immediately with `--apply-now`.
- The passphrase is written only to the system network configuration and is
  never printed. `--force` stages a network on a host without a wireless
  interface.

## After the move

The watcher (`kombify-stackkit-network-watch.timer`, every 60 seconds and 30
seconds after boot) runs `stackkit network rebind --yes --auto`. When the
current address differs from a recorded one it:

1. re-issues the signed LAN resolver record (`lan-dns/a-records.conf`, its MAC
   and the signed manifest); owner identity, secrets and data are unchanged and
   the previous record is kept under `.stackkit/custody/backups`;
2. runs `stackkit generate` and `stackkit apply`, so listeners bind to the new
   address.

It is silent while nothing moved, runs one rebind at a time and waits five
minutes after a failed attempt. A failed apply is retried even though the
recorded addresses already match.

`stackkit apply` enables the watcher on systemd hosts when run as root (skipped
for Fleet members). Opt out with `STACKKIT_NETWORK_WATCH=off` or
`stackkit network watch disable`.

LAN clients and the router's DNS must point at the new resolver address;
`stackkit network status` and `stackkit network rebind` print it.

## Checking and manual re-bind

```sh
stackkit network status --json      # verdict: in-place | moved | unknown
stackkit network rebind --yes       # same re-bind the watcher performs
stackkit network rebind --json      # versioned result: moved, previousAddress,
                                    # currentAddress, applied, wifi{interface,ssid}
```
