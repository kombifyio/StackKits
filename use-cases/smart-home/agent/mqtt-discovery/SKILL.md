# Smart Home MQTT discovery

Verify the current Plan selects smart-home-mqtt=mosquitto before broker operations. Home Assistant, MQTT and Zigbee2MQTT are separate optional workloads. Use the existing native lifecycle MCP/CLI and validate/generate the saved choices. Never install a second broker or create a Kombify device bridge.

The broker consumes its mqtt-password slot from encrypted node custody through the existing private secret-file delivery. Preserve that reference during retry. Client credentials belong in a private upstream client configuration, not arguments, tool outputs or generated artifacts. Verify authenticated publish/subscribe and anonymous denial; an HTTP systree response does not prove MQTT delivery. Retained application messages and the broker persistence file must survive a graceful restart.

The MQTT listener is private to its module network unless the Plan explicitly declares lan-listener. For a broker on the same node as the selected native Home Assistant, explicitly save `workloads.smart-home-mqtt.settings.home-assistant-link: true`, regenerate and apply both workloads. This admits Mosquitto onto Home Assistant's private network; it does not publish TCP1883. Preserve existing broker-only selections without that setting. Do not infer LAN access from a dashboard route or enable TCP1883 publicly. HTTPS dashboard ingress does not encrypt MQTT transport. A different Compose project cannot use an assumed mosquitto service hostname without this admitted network connection.

After both workloads are applied, run the existing `stackkit setup smart-home --owner-approve --complete-onboarding` action. It verifies the signed owner/PocketID binding and configures the selected broker through Home Assistant's authenticated upstream MQTT config-flow, using the broker's encrypted node custody. Retry re-observes an existing integration and preserves its credentials, discovery prefix, TLS and entity exposure choices; a different broker fails closed without rewriting it. A random, unretained publish/subscribe round trip verifies the configured client. Separately observe both discovery of a controlled entity and a subsequent actual state change through Home Assistant's API/MCP; the setup round trip and a published discovery payload alone are not entity-state evidence.

Follow the current workspace database policy. The owner exception permits an admitted, unmodified upstream application to retain its own native internal database on an owned real test server. It does not authorize a local or emulated substitute for a Kombify-owned database. Kombify-owned data still uses live managed Postgres and shared test identities. A missing recorder/database assignment required by the selected contract blocks that dependent flow; never silently disable persistence. The exception grants no schema migration, destructive-change or heavy-acceptance authority beyond the existing governed paths.

For smart-home-zigbee=zigbee2mqtt, require the owner-selected real usb-device, mqtt-server and adapter intent before apply. Reference the same broker credential in the saved Plan when both workloads use that broker; never copy a password into configuration.yaml. The existing native executor delivers a file reference because upstream ZIGBEE2MQTT_CONFIG variables otherwise persist into its data volume. Home Assistant discovery is enabled in this pinned bundle, but radio/device claims still require actual hardware evidence. Do not fabricate a serial device or broker.

Keep upstream setup, automation, playback and device behavior upstream-owned. No provider resource, another node's lifecycle or implicit external access belongs to this skill. Report the proven broker boundary separately from Core/private HTTPS, HA setup/discovery/state, Zigbee hardware, household, current-public-Latest and backup/restore/remove acceptance.
