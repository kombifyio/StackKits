# OpenCloud Files

Confirm the verified Plan selects files=opencloud and the current pinned image before acting. Use the installation's existing StackKits lifecycle MCP or CLI; OpenCloud has no declared native product MCP.

The first service start initializes the native instance configuration using its node-custodied bootstrap environment. Initialization failure stops startup. Repeat start preserves the existing configuration and removes the bootstrap password before the server starts. Never force-overwrite initialized configuration or replace existing data. The native container owns both configuration and filesystem metadata; no SQL server belongs to this workload.

Open the existing private HTTPS Files route. Per-app PocketID and household acceptance is still open; an HTTP health response or successful initialization is not a completed owner login. The existing Cloudreve-specific Files setup action must not be used on OpenCloud. Apply the upstream application's own account and sharing features; do not create another identity or sharing implementation.

Use OpenCloud's supported WebDAV and LibreGraph interfaces for file operations. Preserve its file-native metadata and extended attributes. Backup covers both initialized configuration and data under the existing node-owned Kopia source policy; cache or index health is not functional restore evidence.

Euro-Office integration uses upstream WOPI and remains unverified until the actual Office PostgreSQL role/custody assignment, private HTTPS callback routing and authenticated document open/edit/save flow are admitted. Never start the Office internal PostgreSQL as a substitute. Source selection or a discovery URL does not prove document editing. Do not add provider resources, change PaaS/runtime ownership, or operate another node.
